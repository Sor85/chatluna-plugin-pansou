# Agent Note: PanSou v2 迁移

Status: implemented

## Problem

旧插件依赖 Koishi、ChatLuna v1、LangChain 和 Zod；需要保留 0.0.3 的搜索行为并接入 Cordis 4、v2 原生工具与配置界面。用户明确要求移除插件级工具名称与描述配置。

## Decision

- 独立源码单向同步到 v2 `external/pansou`，只在宿主 workspace 内解析依赖、测试和构建。
- 固定注册 `pansou_search`，使用 `@chatluna/schema` 和 `ctx.tools.define`。工具声明只读，不直接发送消息；权限、禁用、审批与描述覆盖由宿主负责。
- `Config` 直接交给宿主 ui-kit / SchemaForm；旧版没有独立页面或聊天命令，因此不新增前端入口、路由或保存接口。
- 保留全部搜索参数、可覆盖默认类型/总数量、分类限量键、合并结果优先与原始结果回退、重复项和中文格式。
- Schemastery 集合的隐式默认值需移除，保持“省略参数”与“显式空数组”不同；否则原配置的默认网盘范围会被覆盖。地址字段在 checked 包装与表单实际渲染的 inner 两层保留默认值、label 和 description。
- 补齐响应错误码检查、结构校验、认证令牌脱敏、错误文本长度限制及取消传播；拒绝 HTTP 重定向。保持普通搜索失败返回中文文本，真正调用取消交回宿主。
- 不新增本地缓存、重试、去重、业务持久化、模型供应商配置或无关抽象。

## Alternatives considered

- 保留 v1 包装或依赖 LangChain：引入重复生命周期与参数系统，不采用。
- 新增自定义搜索/设置页：旧功能没有此入口，宿主已提供配置与工具调试，不采用。
- 复制旧错误处理缺陷：错误码可能被当作空结果、后端错误可能泄露认证令牌，不采用。

## Consequences

新插件不再提供 toolName/toolDescription，但固定名称仍兼容原来的 pansou_search。模型调用取消和卸载会及时停止 HTTP 请求。验证包括可重复本地 HTTP 回归、真实 Cordis 工具管线、OneBot 三协议群私聊隔离矩阵及用户指定后端的真实模型联调；测试凭据和临时数据不进入源码。
