# Agent Note: PanSou v2 migration

Status: implemented

## Problem

The 0.0.3 plugin depends on Koishi, ChatLuna v1, LangChain and Zod. Its search behavior must move to Cordis 4 and native v2 tools. The user explicitly removed plugin-level tool name and description settings.

## Decision

- Keep an independent source tree and synchronize it one way into `external/pansou`. Resolve, test and build workspace dependencies in the v2 host only.
- Register the stable `pansou_search` name with `@chatluna/schema` and `ctx.tools.define`. Declare a read-only tool that never sends platform messages. Delegate policy, permissions, approval and description overrides to the host.
- Render Config with the host ui-kit / SchemaForm. The old plugin had no custom page or chat command, so no client entry, route or save API is added.
- Preserve all search arguments, overridable defaults, per-drive limits, merged-result precedence, raw-result fallback, duplicates and Chinese output formatting.
- Remove Schemastery's implicit collection defaults so omission and an explicit empty array remain distinct. Preserve URL defaults, labels and descriptions on both the checked wrapper and the inner schema rendered by SchemaForm.
- Validate response shapes and error codes, redact authentication tokens, bound error text, propagate cancellation and reject HTTP redirects. Ordinary search failures retain their text result; actual cancellation returns to the host as a failure.
- Do not introduce local caching, retries, deduplication, persistence or provider configuration.

## Alternatives considered

- Keeping the v1 wrapper would duplicate the host's lifecycle and argument system.
- A custom settings or search page duplicates existing host configuration and tool debugging.
- Preserving the old error-envelope bug would misreport failures as empty results and could disclose authentication tokens in backend error text.

## Consequences

The plugin no longer exposes toolName/toolDescription; its stable registration remains compatible with pansou_search. Tool cancellation and fiber disposal abort pending HTTP requests. Verification covers local HTTP regression tests, the actual Cordis tool pipeline, an isolated OneBot three-implementation group/direct matrix and live model calls against the user-selected backend. Test credentials and temporary data stay outside the source tree.
